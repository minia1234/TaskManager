# 작업 관리자(TaskMonitor) UI 요청서

이 문서는 Windows 작업 관리자를 본뜬 모니터링 앱의 화면 설계와 기능 동작을 정리한 요청서입니다. 현재 구현된 기능을 기준으로 쓰고, 개선이 필요한 부분과 수용 기준을 함께 적었습니다.

## 1. 목적

- 어떤 프로세스가 CPU, 메모리, 디스크, 네트워크, GPU를 쓰는지 한눈에 찾는다.
- 프로그램 아이콘으로 사용자가 바로 알아보게 한다.
- 성능 값을 장치 단위로 자세히 보여 준다(디스크 여러 개, GPU 메모리와 실질 사용량 등).
- 서비스, 시작 프로그램, 사용자 세션을 작업 관리자처럼 관리한다.

## 2. 환경과 제약

- Windows 10(1809 이상) 및 Windows 11, 64비트.
- .NET 10 WinForms. 표는 자체 제작 컨트롤(RowGrid, 소유자 그리기 방식)이다. 화면은 보이는 행만 그린다.
- UI 스레드에서 오래 걸리는 작업을 하지 않는다. 데이터는 백그라운드 스레드가 1초마다 모으고, UI는 완성된 결과만 그린다.
- 관리자 권한 없이 동작해야 한다. 권한이 필요한 값(SATA·USB의 SMART)은 "관리자 권한 필요"라고 표시한다.
- 화면 문구는 한국어다.
- 값을 읽지 못하면 빈칸 대신 "-"를 쓰고, 이유가 있으면 한 줄로 알려 준다.

## 3. 화면 구조

| 영역 | 내용 |
|---|---|
| 메뉴 줄 | 파일(새 작업 실행, 종료), 옵션(항상 위에 표시, 사용하지 않을 때 최소화, 최소화 시 숨기기, 업데이트 속도), 보기(새로 고침 F5, 열 선택, 모두 펼치기, 모두 접기, 이름별 합산), 도움말(정보) |
| 상단 바 | 왼쪽 "작업 관리자" 제목, 가운데 검색창 |
| 왼쪽 탐색 | 프로세스, 성능, 앱 기록, 시작 프로그램, 사용자, 세부 정보, 서비스 (선택된 항목 강조) |
| 페이지 머리글 | 현재 페이지 제목, 오른쪽에 "이름별 합산"(프로세스 페이지만)과 갱신 주기(0.5초, 1초, 4초, 일시 중지) |
| 본문 | 페이지별 내용 (아래 4장) |
| 도구 모음 | 각 페이지 위쪽의 작업 버튼 (선택한 항목이 있을 때만 활성화) |
| 하단 바 | 기록 임계치(%)와 "임계치 이상이면 기록" 체크, 오른쪽에 마지막 갱신 시각, 프로세스 수, 기록 파일 경로 |
| 알림 영역 | 최소화 시 트레이 아이콘. 더블클릭하면 창을 복원한다 |

## 4. 기능별 요구

### 4.1 프로세스 (기본 페이지)

현재 구현:
- 같은 이름의 프로세스를 "이름(개수)"으로 묶는다. 펼치기 화살표로 개별 프로세스를 본다. "이름별 합산"을 끄면 묶지 않는다.
- 열: 이름(아이콘 포함), 상태, CPU, 메모리, 디스크, GPU, PID, 효율성 모드. 열 선택 대화상자로 표시할 열을 고른다.
- 머리글 큰 숫자: 전체 CPU 사용률(임계치 이상이면 빨간색)과 메모리 사용률.
- CPU와 메모리 칸은 값에 따라 파란 계열 색으로 칠한다(4단계).
- 머리글 클릭으로 정렬한다. 검색창으로 이름을 걸러 낸다.
- 시스템 항목: "[시스템] 인터럽트 / DPC", "[시스템] 미귀속 커널 시간".

우클릭 메뉴: 창으로 전환, 작업 끝내기, 작업 트리 끝내기, 효율성 모드(켬·끔), 우선 순위 설정(하위 메뉴), 선호도 설정(대화상자), 덤프 파일 만들기, 파일 위치 열기, 온라인 검색, 속성, 세부 정보로 이동.

요청:
- 아이콘이 없는 항목(시스템 프로세스)은 기본 아이콘을 쓰고, 아이콘이 준비되는 동안은 빈칸으로 둔다. 아이콘은 행을 다시 그릴 때 나타나야 한다.
- 우클릭 메뉴의 위험한 작업(작업 끝내기, 작업 트리 끝내기)은 확인 대화상자를 유지한다.
- 행을 선택하면 하단 상세 영역 또는 도구 모음의 상태가 바뀌어야 한다(선택 항목이 없으면 작업 버튼 비활성).

### 4.2 성능

왼쪽 카드 목록: CPU, 메모리, 디스크(장치마다 한 장), 네트워크(장치마다 한 장), GPU(장치마다 한 장). 각 카드는 작은 그래프와 현재 값을 보여 준다. 카드를 누르면 오른쪽 상세가 바뀐다.

오른쪽 상세: 제목, 큰 숫자(현재 값), 여러 줄의 세부 정보, 큰 그래프(최근 60개 값). CPU와 GPU는 하위 그래프를 함께 보여 준다.

장치별 세부:

| 장치 | 현재 제공하는 값 | 상세 표 |
|---|---|---|
| CPU | 사용률, 사용자·커널 비율, DPC·인터럽트, 속도(GHz)와 기준 속도, 논리 프로세서, 프로세스·스레드·핸들 수, 가동 시간, 코어별 그래프 | 없음 |
| 메모리 | 사용 중, 사용 가능, 전체, 커밋, 캐시, 페이지 풀 | 없음 |
| 디스크 | 활성 시간, 응답 시간, 큐 길이, 읽기·쓰기 속도, 용량, 드라이브 문자, 모델, 온도, 남은 수명, 사용 시간, 전원 켬 횟수, 읽기·쓰기 총량, 펌웨어, 일련번호 | SMART(SATA)와 NVMe 상태 항목 표: ID, 이름, 현재, 최악, 임계값, 원시값, 상태 |
| 네트워크 | 장치 이름, 링크 속도, 사용률, 보냄·받음 속도 | 없음 |
| GPU (NVIDIA) | 사용률, 전용 메모리, 온도, 핫스팟 온도, 메모리 접합부 온도, 팬, 전력과 제한값, 클럭(그래픽·SM·메모리·영상), 성능 상태, 클럭 제한 원인, 인코딩 세션, PCIe 세대·너비·처리량, 엔진별 사용률, VRAM을 쓰는 프로세스 | 상세 표: 항목, 값 (약 25행, 스크롤) |
| GPU (AMD) | ADL로 온도, 사용률, 클럭, VRAM, 전력 (구현됨, 실기 미검증) | 상세 표(NVIDIA와 같은 형식) |

요청:
- 장치 카드가 많을 때(디스크 3개, GPU 여러 개)도 목록을 스크롤해서 모두 볼 수 있어야 한다.
- 상세 영역의 세부 정보 글자가 잘리지 않아야 한다. 줄 수가 많으면 영역이 넓어지거나 스크롤되어야 한다.
- 그래프의 시간축과 값 범위(0~100%, 온도와 전력은 별도 범위)를 한눈에 알 수 있게 한다.
- 장치 이름은 드라이버 이름을 보여 준다(예: "NVIDIA GeForce RTX 4070 SUPER"). 드라이버 이름을 못 찾으면 "GPU 0"처럼 번호만 쓴다.
- 값이 없으면 "-"로 표시하고, 이유가 있으면 상세 영역에 한 줄로 적는다(예: "SATA·USB 장치의 SMART 값은 관리자 권한으로 실행해야 읽을 수 있습니다.").

### 4.3 앱 기록

현재 구현: 기능 없음. "앱 기록은 Windows 사용 기록(ETW·UWP 데이터)을 읽어야 해서 아직 구현하지 않았습니다." 안내 문구만 보인다.

요청: 이 페이지는 나중에 채울 자리다. 지금은 안내 문구를 유지하고, 페이지 구조는 바꾸지 않는다.

### 4.4 시작 프로그램

현재 구현: 레지스트리의 시작 항목을 보여 준다. 열: 이름, 게시자, 상태(사용·사용 안 함), 명령. 도구 모음: 사용, 사용 안 함, 파일 위치 열기. 우클릭 메뉴에도 같은 기능과 속성, 온라인 검색이 있다.

요청: 상태 변경은 즉시 목록에 반영되어야 한다. 권한이 없는 항목(HKLM)은 실패 메시지를 보여 준다.

### 4.5 사용자

현재 구현: 로그온한 세션 목록. 열: 세션, 사용자, 상태(활성·연결 끊김·수신 대기), 창 이름. 도구 모음: 연결 끊기, 로그오프, 메시지 보내기. 로그오프와 연결 끊기는 확인 대화상자를 띄운다.

요청: 세션 작업은 확인을 거친 뒤 실행하고, 결과(성공·실패)를 한 줄로 알려 준다. 현재 사용자 세션을 로그오프하는 것은 위험하므로 경고 문구를 강조한다.

### 4.6 세부 정보

현재 구현: 프로세스를 펼치지 않고 한 줄씩 보는 표. 열: 이름, PID, 상태, 사용자, CPU, 개인 메모리, GPU, 아키텍처, 설명. 열 선택 대화상자를 쓸 수 있다.

요청: 행을 누르면 프로세스 페이지의 같은 항목으로 옮겨 갈 수 있어야 한다(우클릭 "세부 정보로 이동").

### 4.7 서비스

현재 구현: 서비스 목록. 열: 이름, 표시 이름, PID, 상태. 도구 모음: 시작, 중지, 다시 시작, 서비스 열기(services.msc). 우클릭 메뉴에 온라인 검색과 세부 정보로 이동이 있다.

요청: 중지와 다시 시작은 확인 대화상자를 띄운다. 작업이 몇 초 걸릴 수 있으므로 진행 중 표시("서비스 다시 시작 중...")를 보여 준다.

### 4.8 공통 기능

- **검색:** 상단 검색창은 현재 페이지의 이름에서 찾는다. 입력 즉시 목록이 걸러진다.
- **갱신 주기:** 0.5초, 1초, 4초, 일시 중지. 일시 중지 중에도 F5로 한 번 갱신할 수 있다. 설정은 다음 실행 때도 유지된다.
- **정렬과 묶기:** 머리글 클릭으로 정렬하고, 묶기는 "이름별 합산"으로 켜고 끈다.
- **열 선택:** 프로세스와 세부 정보 페이지에서 표시할 열을 고른다. 선택은 저장된다.
- **항상 위에 표시, 최소화 동작:** 옵션 메뉴에서 켜고 끈다. 최소화 시 숨기기를 켜면 트레이로 들어간다.
- **기록 임계치:** 하단 바에서 임계치(%)를 정하고, 전체 CPU가 넘으면 기록 파일에 남길지 정한다. 임계치 이상이면 CPU 큰 숫자가 빨간색이 된다.
- **상태 바:** 마지막 갱신 시각, 프로세스 수, 기록 파일 경로를 보여 준다.

## 5. 디자인 가이드

Windows 11 작업 관리자의 느낌을 따른다. 아래 색과 간격은 현재 구현 값이다.

| 요소 | 값 |
|---|---|
| 상단 바 배경 | #EDF3F8 |
| 탐색·하단 바 배경 | #F3F3F3 |
| 탐색 선택 강조 | #E0ECF9 |
| 행 선택 강조 | #CCE8FF |
| 격자선 | #E5E5E5 |
| 히트맵 4단계 | #D6F1FF, #9CDDFF, #79CFFF, #58BEFF |
| 임계치 초과 | 빨간색(Firebrick) |
| 제목 글꼴 | Segoe UI Variable Display 16pt(페이지 제목), 18pt(상세 제목) |
| 본문 글꼴 | Segoe UI Variable Text 9pt |
| 행 높이 | 28px |
| 머리글 높이 | 32px (큰 숫자 열이 있으면 64px) |

요청:
- 밝은 테마를 기본으로 하고, 시스템 다크 모드에 맞는 색을 준비하면 좋다(현재 없음).
- 아이콘은 16px로 표시한다.
- 크기를 줄여도 가로 스크롤 없이 주요 열이 보여야 한다.

## 6. 수용 기준

1. 프로세스 페이지에서 1초마다 목록이 바뀌어도 클릭과 스크롤이 끊기지 않는다.
2. 아이콘이 있는 프로그램은 목록에 아이콘이 보인다.
3. 성능 페이지에서 디스크 3개, 네트워크 2개, GPU 2개가 모두 카드로 보이고, 각 카드를 누르면 상세가 바뀐다.
4. NVIDIA GPU를 고르면 상세 표에 온도, 핫스팟 온도, 메모리 접합부 온도, VRAM, 전력, 클럭이 보인다.
5. 디스크를 고르면 SMART(또는 NVMe) 표가 보이고, 임계값을 넘은 항목은 빨간색이다.
6. 권한이 없어 값을 못 읽는 경우, 빈칸 없이 "-"와 한 줄 안내가 보인다.
7. 우클릭 메뉴의 파괴적 작업(작업 끝내기, 서비스 중지, 로그오프)은 확인 대화상자를 거친다.
8. 최소화 시 트레이로 들어가고, 트레이 아이콘을 더블클릭하면 복원된다.
9. 갱신 주기와 열 선택, 항상 위에 표시 설정은 앱을 다시 실행해도 유지된다.

## 7. 알려진 한계 (디자인에 반영해야 함)

- AMD GPU 값은 실제 AMD GPU에서 검증하지 않았다. 화면은 값이 없으면 "-"로 보여야 한다.
- 앱 기록 페이지는 아직 기능이 없다.
- 서비스 시작·중지와 세션 작업은 이 PC에서 실제 동작을 시험하지 않았다(상태가 바뀌는 시험이므로 제외함).
- 프로세스별 네트워크 사용량은 구현하지 않았다.
- 프로세스별 VRAM은 Windows GPU 카운터로 읽는다. 값이 없는 드라이버에서는 목록이 비어 있을 수 있다. 그 사실을 한 줄로 알려야 한다.

## 8. 요청하는 산출물

1. **화면 설계안:** 위 3장의 화면 구조를 기준으로 페이지별 배치(특히 성능 페이지의 오른쪽 상세 영역과 GPU 표의 크기)를 정리한다.
2. **기능별 수정 범위:** 바꿀 파일(주로 `PerformancePage.cs`, `GridPage.cs`, `RowGrid.cs`, `MainForm.cs`)과 바꾸지 않을 부분을 나눈다.
3. **단계별 구현:** 우선순위는 (1) 성능 페이지 상세 영역 잘림 해결, (2) 장치 카드 스크롤과 상세 표 개선, (3) 다크 테마, (4) 앱 기록 구조 준비 순서다.
4. **검증 방법:** 자체 검증(`TaskMonitor.exe --selftest 결과.txt`)으로 값이 읽히는지 확인하고, 실행 화면을 캡처해서 각 수용 기준을 확인한다.
